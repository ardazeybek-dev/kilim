Inside the CRDT

Every character has a unique id site:seq and a Lamport clock. Deleted characters stay as tombstones so late-arriving edits can still find where they belong.

Real sync across browser tabs

How it works

  1. Every insert remembers its left neighbour (its origin) instead of an index — indices change, ids don't.
  2. Concurrent inserts after the same origin are ordered by (lamport, site), newest first. Every replica runs the same rule, so every replica picks the same order.
  3. Deletes leave tombstones, so an insert that arrives late can still attach to a deleted neighbour.
  4. Operations are idempotent (duplicates are ignored) and buffered until their dependency arrives, so delivery order does not matter.
  5. Version vectors let a replica that was offline ask for exactly the operations it missed.
import init, { Doc } from "kilim";
await init();
const doc = new Doc(siteId);
const ops = doc.insert(0, "merhaba");   // broadcast these
other.applyRemote(ops);                  // any order, any number of times
